Documentation

Welcome to Trunq

Trunq is a fast, free desktop app for PostgreSQL. This guide covers everything from installing it and connecting to your first database to the safety features that help keep production healthy.

Install Trunq →Download for macOS, Windows or Linux. Connect in a minute →Add a database and run your first query. Stay out of trouble →How Trunq protects your databases.

Install

Download the latest version from the Releases page and choose the file for your system:

SystemFileHow to install
macOS 11+ (Apple Silicon & Intel)Trunq-<version>-macos-universal.dmgOpen it and drag Trunq to Applications.
Windows 10 / 11 (64-bit)Trunq-<version>-windows-x86_64.zipUnzip it and run Trunq.exe.
Debian / Ubuntu (64-bit)trunq_<version>_amd64.debsudo apt install ./trunq_<version>_amd64.deb
Other Linux (64-bit)trunq-<version>-linux-x86_64.tar.gzUnpack it and run ./trunq.
macOS says it "can't be opened because it is from an unidentified developer"? Right-click Trunq.app → Open once. After that it opens normally.

Every release includes SHA-256 checksums in SHA256SUMS.txt, so you can verify your download. If you'd rather compile Trunq yourself, see Build from source.

Your first connection

  1. Click New connection (or the plug icon in the top bar).
  2. Paste a connection URL such as postgres://user:pass@db.example.com:5432/app?sslmode=require and press Apply, or fill in the host, port, database and user yourself.
  3. Press Test connection, then Save. Give production connections a red colour. The colour appears on every tab and above the editor, so you always know where you are.
  4. Browse your database. The connection appears in the sidebar. Expand it to see databases, schemas, tables, views, functions and types. Double-click a table to open its data, or right-click anything for more actions.
  5. Write a query. Press ⌘T for a new SQL editor, then ⌘⏎ to run the statement under the cursor.

Passwords are saved in your operating system's keychain, never in plain text.

Want something to play with? The repository includes a sample shop database with customers, orders, a million analytics events, views, functions and JSON: 
createdb shop
psql -d shop -f dev/sample.sql

Connection options

Trunq speaks the PostgreSQL protocol directly and supports the usual ways of connecting:

  • Encryption (TLS): every sslmode from disable to verify-full.
  • Sign-in methods: SCRAM-SHA-256, MD5 and trust.
  • Unix sockets: enter the socket directory (for example /tmp) as the host.
  • ~/.pgpass: picked up automatically.
  • Connection URLs: paste a postgres:// URL and Trunq fills in the form.

Per-connection safety settings

  • Colour: shown on every tab of that connection. Make production red.
  • Read-only: prevents accidental writes.
  • Statement timeout: stops runaway queries automatically.

Azure & Microsoft Entra ID

Azure Database for PostgreSQL accepts a short-lived (about one hour) Entra access token as the password. Trunq gets this token and refreshes it automatically before every new connection, so you never have to paste tokens by hand.

  1. Create a new connection with a host such as myserver.postgres.database.azure.com. Trunq recognises Azure hosts and sets SSL to require.
  2. Set Authentication to Microsoft Entra ID.
  3. Choose the Azure cloud. Trunq detects it from the host name:
    • Azure (global): *.postgres.database.azure.com
    • Azure China (21Vianet): *.postgres.database.chinacloudapi.cn
    • Azure US Government: *.postgres.database.usgovcloudapi.net
  4. Pick a sign-in method:
    • Interactive (browser): opens the Microsoft sign-in page. After the first sign-in, the refresh token is kept in your keychain and new tokens are created silently for about 90 days.
    • Device code: for machines without a browser (remote desktops, SSH). Trunq shows a code to enter at microsoft.com/devicelogin or the China equivalent.
    • Azure CLI: reuses your az login session. For China, run az cloud set --name AzureChinaCloud first.
  5. User: your Entra user principal (for example jane@contoso.com) or the name of the Entra group or role that was granted access. Leave it empty to use the signed-in account.
  6. Optional: a Tenant (contoso.onmicrosoft.com or a tenant ID). Under Advanced you can set your own client ID if your organisation blocks the Azure CLI public client.

Writing queries

The SQL editor understands PostgreSQL and helps you as you type.

  • Smart autocompletion for tables, columns, schemas, functions and keywords. It understands aliases: typing o. suggests the columns of orders o.
  • Run what you need: the statement under the cursor (⌘⏎), the selection, or the whole script (⇧⌘⏎). Each result opens in its own tab.
  • Clear errors: mistakes are underlined at the exact position PostgreSQL reports.
  • Parameters: write WHERE id = :id and Trunq asks for the value. Values are remembered per tab.
  • Handy editing: formatter, comment toggle, indent and outdent, and duplicate line.
  • Files & history: open and save .sql files (or drop them on the window), search your query history, and your workspace is restored when you restart.
  • Messages: notices and NOTIFY events appear in the Messages tab.

Working with results

Results never freeze the app, however big they are.

  • Streaming: the first page contains up to 1,000 rows and more load as you scroll. Server execution still depends on the query and database.
  • Smooth grid: millions of rows and hundreds of columns scroll at full frame rate, with sticky headers, row numbers, and resizable or auto-fit columns.
  • Spreadsheet-style selection with live Σ / avg / min / max of the selected numbers.
  • Sort and filter instantly.
  • Copy or export as TSV, CSV, JSON, Markdown, SQL INSERT statements or an IN (…) list.
  • Follow foreign keys: ⌘-click a foreign key value to jump to the row it points to, in any result.
  • Value viewer with pretty-printed JSON.

Editing data

  1. Double-click a table to browse it. Use the WHERE / ORDER BY bar to narrow it down. Key icons mark the primary key.
  2. Edit cells inline, or add, duplicate and delete rows, and set values to NULL. Changed cells are highlighted.
  3. Preview the generated SQL, then save everything in one transaction.

Charts

Turn any result into a chart with one click. Time or numeric X values become a line chart, and categories become bars. The palette is colour-blind safe, with hover tooltips, a legend and direct labels. Trunq never mixes wildly different scales on one axis.

Importing CSV files

Drop a CSV or TSV file onto the window. Trunq works out the delimiter, header, column names and column types (integer, bigint, numeric, boolean, date, timestamptz, uuid, jsonb).

Create a new table or add to an existing one. The data is streamed in a single transaction with live progress, which is the fastest way to load data into PostgreSQL.

ER diagrams & metadata

Right-click a database, schema or table and choose ER diagram, or find it in the command palette. Diagrams reuse the loaded catalog, so opening one needs no additional database query.

Pan, zoom, drag tables, inspect columns and keys, or export SVG and Mermaid. Opening from a table focuses its neighbourhood; opening from a schema limits the graph to that schema.

Inspect the catalog

Expand a table for its indexes, constraints, triggers and policies. Hover for index methods, validity, constraint definitions and trigger functions. An RLS indicator marks enabled row security. Server-level Roles and Tablespaces show attributes and ownership; right-click a role to copy its DDL.

Find expensive statements

Right-click a database → Slow queries (pg_stat_statements). Review and run the generated SQL to inspect calls, execution time, returned rows and buffer/temp-block counters. Your DBA must preload and install pg_stat_statements; Trunq does not change the server configuration. Access to other users’ query text depends on your role.

Docker & Docker Hub

The Docker image runs the native client in a browser-accessible noVNC desktop. Use a native release for maximum interactive performance: the container adds software rendering and desktop streaming.

docker compose up --build -d

Open localhost:8080/vnc.html. The virtual screen scales to your browser window. The Compose file keeps the workspace in a volume and publishes only on loopback. The desktop has no built-in authentication; keep that binding for local use or use an SSH tunnel for remote access. Connect to host PostgreSQL via host.docker.internal.

Publish your image

Configure the repository variable DOCKERHUB_USERNAME and secret DOCKERHUB_TOKEN. The Docker workflow builds and smoke-tests the desktop before publishing amd64 and arm64 images on version tags or an explicit manual run. Stable version tags update latest; manual runs publish a commit tag.

See the full Docker guide for manual Buildx commands, the native target, credentials and remote access.

Performance you can measure

Trunq pages results through PostgreSQL portals and draws visible grid cells. Empty searches and selection aggregates stay cached until the relevant data, view or edits change. Search, sort and hidden empty columns include pending edits.

cargo test --release --locked bench_empty_filter_million -- --ignored --nocapture
TRUNQ_TEST_DATABASE_URL=postgres://… cargo test --release --locked bench_fetch_million -- --ignored --nocapture

Fetching, server execution and drawing are different costs. A fast first page is not a guarantee that any query will execute quickly. The performance report describes the workload and measured limits; the research notes distinguish shipped features from future PostgreSQL integrations.

Finding your way around

  • Command palette (⌘K): fuzzy-jump to any table, view, function, connection or command.
  • Object tree: databases, schemas, tables (expand to see columns, keys and foreign keys), views, materialized views, sequences, functions and types, with row estimates and sizes.
  • Generate SQL from the right-click menu: SELECT / INSERT / UPDATE / DELETE, DDL, function definitions and maintenance commands.
  • Query plans: EXPLAIN and EXPLAIN ANALYZE are shown visually, with each step's share of the time, loop counts and row-estimate warnings.

Safety features

Trunq is designed to help you avoid the mistakes that cause outages.

Lock detective

When a query has been running for more than 1.5 seconds, Trunq shows what it's waiting for and which session is blocking it, including the user, application, query and transaction age. One click cancels that session's query or terminates the session.

Dry run

Press ⌥⌘⏎ to run an INSERT, UPDATE or DELETE inside a transaction. Trunq shows exactly which rows would change and then always rolls back.

Migration linter

Before running a change that would block or rewrite a table, Trunq explains the risk and the safe alternative. Plain CREATE INDEX statements get a one-click Add CONCURRENTLY fix. Trunq checks for:

  • Plain CREATE INDEX
  • Column type changes
  • SET NOT NULL
  • Foreign keys without NOT VALID
  • Volatile defaults
  • VACUUM FULL

Confirmations & guards

  • Trunq asks before running an UPDATE or DELETE without WHERE, a DROP, or a TRUNCATE.
  • Forgotten-transaction guard: a banner appears when a tab has held a transaction (and its locks) open for more than a minute.
  • Live progress for CREATE INDEX, VACUUM, ANALYZE, COPY and CLUSTER.

Health check

One click finds the problems that cause real outages. Each finding comes with generated fix SQL for you to review, and nothing runs automatically.

  • Integer IDs close to running out
  • Transaction-ID wraparound
  • Inactive replication slots filling the disk
  • Foreign keys without indexes
  • Invalid, duplicate or unused indexes
  • Bloated or never-analyzed tables
  • Long-running transactions
  • Tables without a primary key
  • Low cache-hit ratio

Connection management

Trunq never leaks connections.

  • Every connection belongs to exactly one tab or sidebar item, and closes when that goes away. A running statement is cancelled first.
  • Idle query tabs disconnect after 15 minutes and reconnect transparently when you come back.
  • The status bar shows the live connection count. Click it to see every connection (purpose, PID, age) and close any of them.
  • Each connection sets application_name (for example Trunq — Query 3), so you can find it in pg_stat_activity.
  • Background metadata connections use lock_timeout and statement_timeout and never take table locks, so they can't get stuck behind a migration.
  • TCP keep-alive detects dead networks, and everything is closed cleanly on exit.

Troubleshooting

"password authentication failed" or "no password supplied"
Type the password in the field that appears in the sidebar or above the editor. It's remembered for the session, and saved in the keychain if Save in keychain is on.
Azure: AADSTS… errors
Check the tenant, check that your account (or its group) was added as an Entra admin or role on the server, and check that the right cloud is selected. If your organisation's policy blocks the browser flow, try Device code.
The app window is blank on an old GPU or virtual machine
Start Trunq with WGPU_BACKEND=gl to use OpenGL.
Keychain prompts on macOS
Click Always Allow once so Trunq can read its saved passwords.
macOS won't open the app
Right-click Trunq.app → Open once, or run xattr -dr com.apple.quarantine /Applications/Trunq.app.

Still stuck? Open an issue on GitHub.

Build from source

You'll need Rust. The first build downloads and compiles dependencies and takes a few minutes. Later builds are incremental.

# 1. Install Rust (once)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"

# 2. Get the code, build Trunq.app and copy it to /Applications
git clone https://github.com/IssamElNass/trunq.git trunq
cd trunq
./scripts/bundle-macos.sh --install

Use ./scripts/bundle-macos.sh to only build Trunq.app, or add --dmg to also create a shareable Trunq.dmg. Requires macOS 11+ and the Xcode command line tools (xcode-select --install).

# Debian / Ubuntu build dependencies
sudo apt install build-essential pkg-config libssl-dev libxkbcommon-dev libwayland-dev \
  libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev libgtk-3-dev libdbus-1-dev

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
git clone https://github.com/IssamElNass/trunq.git trunq && cd trunq
cargo build --release
sudo install -m 755 target/release/trunq /usr/local/bin/trunq

On Fedora: sudo dnf install gcc pkgconf openssl-devel libxkbcommon-devel wayland-devel gtk3-devel dbus-devel.

Install Rust and choose the MSVC toolchain (it installs the Visual Studio build tools). Then, in a terminal:

git clone https://github.com/IssamElNass/trunq.git trunq
cd trunq
cargo build --release
.\target\release\trunq.exe

Scripted UI runs

Load dev/sample.sql into a disposable database and run TRUNQ_TEST_DATABASE_URL=postgres://… python3 scripts/screenshots.py. It captures twelve views in a temporary workspace and converts them to WebP when cwebp is available. TRUNQ_CONFIG_DIR selects an isolated configuration directory.

For visual checks without OS permissions, drive the app with TRUNQ_SCRIPT:

TRUNQ_SCRIPT="wait:3;run;wait:2;shot:/tmp/query.png;open:shop.orders;wait:2;shot:/tmp/table.png;quit" cargo run

Steps: wait:<s>, run, runall, dryrun, explain[:analyze], sql:<text> (separate statements with ;;), open:<schema.table>, tab:<n>, palette:<query>, health, newconn, connections, theme:light|dark, shot:<file.png>, quit. Scripted runs never overwrite your saved workspace.

Releases

  1. Bump version in Cargo.toml and add the notes to CHANGELOG.md.
  2. Tag and push: git tag v0.2.0 && git push origin v0.2.0.
  3. GitHub Actions builds the macOS .dmg, Linux .deb and .tar.gz, and the Windows .zip, generates SHA256SUMS.txt and publishes the release.
